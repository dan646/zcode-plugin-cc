Передаёт написание и ревью кода из Claude Code в **ZCode** — агентную среду
для программирования от [Z.ai](https://z.ai) на моделях GLM (GLM-5.3,
GLM-5.3-Flash, GLM-5-Turbo).

Claude остаётся оркестратором: планирует, делегирует и проверяет результат.
ZCode пишет код или даёт второе мнение по диффу. Идея та же, что у
[`openai/codex-plugin-cc`](https://github.com/openai/codex-plugin-cc), только
вместо Codex/GPT — ZCode/GLM.

```text
/zcode:code добавь валидацию в форму регистрации и покрой её тестами
/zcode:review main
```

## Возможности

- **`/zcode:code`**: ZCode реализует задачу прямо в рабочем дереве, прогоняет
  тесты проекта и сообщает, что изменил.
- **`/zcode:review`**: отправляет git-дифф (рабочее дерево, ветку, коммит или
  путь) в ZCode на ревью с упором на корректность и безопасность.
- **Область правок**: глобы `--allow` / `--deny` ограничивают, какие файлы
  могут трогать файловые инструменты ZCode.
- **Живой прогресс**: по строке на каждый вызов инструмента (`Read src/index.mjs`,
  `Bash npm test`) и heartbeat, который отличает долго думающую модель от
  оборванного соединения.
- **Сводка изменений**: после хода `code` — список созданных, изменённых и
  удалённых файлов по git, где правки ZCode отделены от остальных.
- **Предохранители**: таймаут хода, `--idle-after-write` и `--max-tool-calls`,
  у каждого свой код выхода.
- **Без зависимостей**: голый Node.js, `npm install` не нужен. Плагин не
  читает, не хранит и не печатает ваш API-ключ.

## Требования

- **[Claude Code](https://claude.com/claude-code)** с поддержкой плагинов.
- **ZCode.app**. CLI `zcode` идёт внутри приложения, отдельно ставить ничего не
  нужно. Отдельно установленный `zcode` на `PATH` тоже подойдёт.
- **Node.js 18.18+**.
- **Ключ Z.ai API** в переменной окружения `ZAI_API_KEY`.

Разработано и проверено на macOS.

## Установка

В Claude Code добавьте этот репозиторий как маркетплейс плагинов и поставьте
плагин:

```text
/plugin marketplace add dan646/zcode-plugin-cc
/plugin install zcode@zcode-plugin-cc
/reload-plugins
```

Чтобы поставить из локального клона, передайте путь:
`/plugin marketplace add /path/to/zcode-plugin-cc`.

## Настройка

1. Экспортируйте ключ **до** запуска Claude Code. ZCode запускается дочерним
   процессом и наследует окружение. Плагин только передаёт его дальше.

   ```bash
   export ZAI_API_KEY="ваш-ключ"
   ```

2. Один раз авторизуйте ZCode, если ещё не делали этого:

   ```bash
   zcode login
   ```

   Если `zcode` нет на `PATH`, запустите CLI из приложения:
   `node /Applications/ZCode.app/Contents/Resources/glm/zcode.cjs login`.

3. Проверьте, что всё подключено:

   ```text
   /zcode:setup
   ```

   ```text
   ZCode CLI: /usr/local/bin/node /Applications/ZCode.app/Contents/Resources/glm/zcode.cjs
   Provider configured: yes
   Current model: zai/glm-5.3-flash
   ```

`/zcode:setup` только диагностирует. Он не запускает `zcode login` и не трогает
учётные данные, а говорит, что сделать.

## Использование

### Делегировать задачу

```text
/zcode:code добавь хелпер slugify() в src/utils и покрой его тестами
```

ZCode — отдельный процесс. Он **не видит разговор в Claude Code**, только текст
задачи и то, что сам прочитает в рабочей директории (`AGENTS.md` / `CLAUDE.md`
он подхватывает сам). Пишите задачу так, чтобы она была понятна без контекста.

Ограничить, куда ZCode может писать:

```text
/zcode:code --allow 'app/**' --allow 'tests/**' --deny 'app/secrets/**' добавь проверку email
```

### Ревью изменений

```text
/zcode:review               # рабочее дерево против HEAD (staged + unstaged)
/zcode:review main          # что внесла ветка с момента ответвления от main
/zcode:review a1b2c3d       # изменения после коммита
/zcode:review src/billing   # изменения рабочего дерева в одном пути
```

Ветка или коммит — это **база** для сравнения, как в пулл-реквесте.
`/zcode:review main` ревьюит вашу ветку, а не `main`.

Новые неотслеживаемые файлы перечисляются для ZCode, но в `git diff` не
попадают. Чтобы их содержимое ушло на ревью диффом, сначала сделайте `git add`.

### Проверить состояние

```text
/zcode:status
```

Показывает путь к CLI, настроен ли провайдер, текущую модель и модели в
каталоге.

## Команды

| Команда | Что делает |
|---|---|
| `/zcode:setup` | Диагностика: находит CLI и проверяет, что провайдер моделей настроен. |
| `/zcode:code <задача>` | Реализует задачу в рабочей директории. |
| `/zcode:review [база\|путь]` | Ревью диффа. По умолчанию — рабочее дерево против `HEAD`. |
| `/zcode:status` | Путь к CLI, готовность провайдера, текущая модель и каталог моделей. |

## Флаги

| Флаг | Где | Описание |
|---|---|---|
| `--model <id>` | все | Модель на сессию, например `glm-5.3` или `zai/glm-5.3`. По умолчанию: `code` → `glm-5.3-flash`, `review` → `glm-5.3`. |
| `--cwd <path>` | все | Рабочая директория. По умолчанию — текущая. |
| `--json` | `setup`, `status` | Машиночитаемый вывод. |
| `--timeout <сек>` | `code`, `review` | Таймаут хода. По умолчанию: `code` 2700 с (45 мин), `review` 1800 с (30 мин). |
| `--idle-after-write <сек>` | `code`, `review` | Остановить, если после первой записи столько времени не было новой. Выключен по умолчанию. |
| `--max-tool-calls <n>` | `code`, `review` | Остановить после более чем `n` вызовов инструментов. Выключен по умолчанию. |
| `--mode <build\|edit\|plan\|yolo>` | `code`, `review` | Собственный режим работы ZCode на этот ход. |
| `--allow <glob>` | `code` | Повторяемый. Разрешить файловые инструменты только в совпавших путях. |
| `--deny <glob>` | `code` | Повторяемый. Запретить совпавшие пути. Важнее `--allow`. |
| `--no-stream` | `code`, `review` | Скрыть потоковый текст модели; вызовы инструментов, heartbeat и сводка остаются. |
| `--quiet` | `code`, `review` | Скрыть весь прогресс; печатаются только финальный ответ и строка с usage. |

Прогресс идёт в **stderr**, финальный ответ ZCode — в **stdout**, так что вывод
можно пайпить.

### Почему таймауты такие длинные

`code` и `review` — многораундовые ходы с вызовом инструментов, а не один
запрос. Замер на реальном проекте (Laravel в docker): один юнит работы занимал
20–30 минут. Первые 10–15 минут не было никакого вывода, пока модель думала,
потом всё появлялось разом. Дефолты покрывают верх этого диапазона плюс раунд
исправлений. Ваш `--timeout` всегда важнее дефолта.

### Предохранители

- **`--idle-after-write <сек>`** останавливает ход, если после первой принятой
  записи (`Write`/`Edit`) столько времени не было новой. Ставьте значение
  **больше самого долгого прогона тестов и линтеров**: в протоколе нет события
  «команда завершилась», поэтому модель, ждущая долгий `Bash`, неотличима от
  бездействующей. Ход без единой записи этот флаг не останавливает.
- **`--max-tool-calls <n>`** останавливает ход после более чем `n` объявленных
  вызовов инструментов, включая отклонённые областью правок.

При остановке хода в stderr печатается одна строка с причиной, порогом, числом
вызовов и давностью последней записи. В stdout — хвост незавершённого текста
модели с явной пометкой, что ответ не завершён.

## Область правок: `--allow` и `--deny`

Шаблоны задаются относительно `--cwd` и поддерживают `**`, `*` и `?`: например
`app/**`, `*.md`, `database/migrations/*.php`.

- Если есть хотя бы один `--allow`, любой инструмент, в чьём входе есть
  `file_path`, `notebook_path` или `path`, разрешён только в совпавших путях.
- `--deny` важнее `--allow`.
- При включённой области пути вне `--cwd` всегда отклоняются.
- На macOS сравнение не зависит от регистра, поэтому `Resources/JS/…` не обходит
  запрет `resources/js/**`.
- Активная область печатается в начале хода, отклонённые попытки — в сводке.

> [!WARNING]
> Область правок — **не песочница для `Bash`**. Shell-команды остаются
> разрешены, чтобы ZCode мог гонять тесты и линтеры, и такая команда может
> изменить файлы в обход области. Надёжно извлечь записываемые пути из
> shell-текста нельзя.

Область работает только с `--mode build` или `--mode plan`. Без `--mode` плагин
явно выбирает `build`. `edit` и `yolo` отклоняются до начала хода: в этих
режимах ZCode сам одобряет запись, и область применить невозможно.

## `--mode` — это не право на запись

`--mode` задаёт **собственное поведение ZCode** на ход через `session/setMode`:

| Режим | Поведение |
|---|---|
| `build` | Обычный рабочий режим ZCode. |
| `edit` | Правка только существующих файлов. |
| `plan` | Предложить план, не трогая файлы. |
| `yolo` | Без внутренних подтверждений ZCode. |

Он не решает, даёт ли плагин право на запись. `review` и `code` без области
правок дают его всегда: ZCode нужны инструменты, чтобы читать код. `--mode plan`
заставляет ZCode *решить* ничего не менять, но это не гарантированный
read-only прогон.

## Вывод

Во время хода прогресс печатается в stderr:

```text
[zcode] prompt_started
[zcode] tool: Read src/index.mjs
[zcode] tool: Write tests/slug.test.mjs
[zcode] tool: Bash npm test
```

Пути внутри `--cwd` показываются относительными, пути в домашней директории
вне `--cwd` сокращаются до `~/…`. Аргументы инструментов обрезаются, а
секрето-подобные поля `"apiKey"` вычищаются.

**Heartbeat.** Если сервер 30 с ничего не присылал, плагин опрашивает
`session/usage` и печатает строку состояния. Опрос повторяется, пока ход молчит:

```text
[zcode] 12m30s · жив · запросов 4 (+1) · токенов 210k (+48k) · последняя запись 2m10s назад
[zcode] 18m00s · жив · без прогресса 5m — модель думает · записей ещё не было
```

Вторая строка — **не ошибка**. Сервер отвечает, модель просто думает уже
5 минут. Плагин никогда не прерывает ход по этому признаку. Если 3 опроса
подряд остались без ответа, связь действительно потеряна, и ход сразу
завершается ошибкой `stopped responding`, а не ждёт до конца таймаута.

**Сводка изменений.** После хода `code`:

```text
[zcode] изменённые файлы:
[zcode]   src/slug.mjs (создан)
[zcode]   tests/slug.test.mjs (создан)
```

## Коды выхода

| Код | Значение |
|---|---|
| `0` | Успех. |
| `1` | Ошибка команды: не найден CLI, провайдер не настроен, нет задачи, не git-репозиторий или нечего ревьюить. |
| `2` | Ход ZCode завершился ошибкой (`turn.failed`). |
| `3` | Ход остановлен (таймаут, `--idle-after-write`, `--max-tool-calls`), записей **не было**. |
| `4` | Ход остановлен **после** записей. Работа могла быть сделана частично — проверьте дифф. |

## Решение проблем

**`Could not locate the ZCode CLI`**: CLI ищется в таком порядке: `$ZCODE_CLI`
→ CLI внутри `/Applications/ZCode.app` → `zcode` на `PATH`. Поставьте
ZCode.app, добавьте `zcode` в `PATH` или задайте `ZCODE_CLI` абсолютным путём до
`zcode` / `zcode.cjs`. Путь должен вести к файлу, а не к бандлу `.app`.

**`Provider configured: no`**: один раз выполните `zcode login` с
экспортированным `ZAI_API_KEY`, затем снова `/zcode:setup`.

**`session/setModel` не знает модель**: свежий `zcode login` может
зарегистрировать только `glm-5.1` / `glm-4.7`, без дефолтных `glm-5.3`.
Посмотрите каталог через `/zcode:status` и передайте доступную модель:
`--model glm-5.1`.

**`ZCode app-server stopped responding`**: несколько опросов heartbeat подряд
не получили ответа — связь действительно оборвалась, модель не просто думала.
Проверьте, что ZCode ещё работает, и повторите команду.

**`review`: «is not inside a git repository»**: запустите Claude Code из
репозитория или передайте его через `--cwd`.

**`review`: «No changes to review»**: рабочее дерево совпадает с `HEAD`, и
неотслеживаемых файлов нет. Проверьте `--cwd`.

**`ZCode turn failed`** (код выхода 2): в stderr будут `code` и `retryable`.
При `retryable: true` повторите команду. Если ошибка повторяется стабильно,
проверьте, что `ZAI_API_KEY` задан до запуска Claude Code и что ключ
действителен.

## Как это устроено

```text
/zcode:<команда>   (слэш-команда в Claude Code)
      │
      ▼
scripts/zcode-companion.mjs        разбор аргументов, вывод, коды выхода
      │
      ▼
lib/session.mjs                    runTurn(): один ход, heartbeat, правила остановки
      │
      ▼
lib/protocol.mjs                   клиент ZCode Protocol
      │   JSON построчно через stdio
      ▼
zcode app-server                   агент ZCode на GLM
```

Плагин запускает `zcode app-server` и общается с ним по ZCode Protocol:
построчный JSON через stdio (не JSON-RPC 2.0). Он создаёт сессию, задаёт модель
и режим, отправляет самодостаточный промпт из `prompts/`, отвечает на запросы
`interaction/requestPermission` в соответствии с областью правок и транслирует
события в прогресс. Заметки о протоколе — в
[`docs/zcode-protocol-recon.md`](docs/zcode-protocol-recon.md).

## Разработка

Тесты запускаются встроенным раннером Node, пакеты не нужны:

```bash
npm test
```

```text
.claude-plugin/marketplace.json   манифест маркетплейса
plugins/zcode/
  .claude-plugin/plugin.json      манифест плагина
  commands/                       слэш-команды (setup, code, review, status)
  prompts/                        шаблоны промптов для ZCode
  scripts/zcode-companion.mjs     точка входа
  scripts/lib/                    протокол, сессия, дифф, область правок, поиск CLI
tests/                            юнит-тесты и фейковый app-server
probes/                           ручные скрипты для живого ZCode
docs/                             заметки о протоколе
```
