# zcode-plugin-cc

Плагин `zcode` для Claude Code: делегирует написание и ревью кода в **ZCode** —
агентную среду от Z.ai на моделях GLM (GLM-5.3, GLM-5.3-Flash, GLM-5-Turbo).

Идея та же, что у `openai/codex-plugin-cc`, только вместо Codex/GPT — ZCode/GLM.

## Статус

В разработке. Каркас плагина, протокольная разведка и слэш-команды готовы.

## Требования

- Установленный **ZCode.app** (CLI идёт внутри приложения, отдельно ставить не нужно).
- **Node.js 18.18+**.
- Ключ Z.AI API, доступный через переменную окружения `ZAI_API_KEY`.

Зависимостей времени выполнения у плагина нет — он рассчитан на голый Node,
`npm install` не требуется.

## Установка в Claude Code

Добавить локальный маркетплейс (путь к этому репозиторию):

```bash
/plugin marketplace add /path/to/zcode-plugin-cc
```

Поставить плагин:

```bash
/plugin install zcode@zcode-plugin-cc
```

Перезагрузить плагины:

```bash
/reload-plugins
```

## Настройка ключа

Плагин не хранит и не читает ключ из конфигурационных файлов — он ссылается на
переменную окружения по имени и передаёт её ZCode как есть. Перед запуском
Claude Code задайте:

```bash
export ZAI_API_KEY="..."
```

## Команды

Все команды идут через один скрипт-точку входа,
`plugins/zcode/scripts/zcode-companion.mjs`, и никогда не обращаются к
транспорту напрямую — только через `lib/session.mjs` (`runTurn`,
`readWorkspaceState`).

| Команда | Что делает |
|---|---|
| `/zcode:setup` | Диагностика: резолвит CLI, проверяет через `workspace/readState`, настроен ли провайдер. Ничего не устанавливает и не запускает `zcode login` сама — только говорит, что делать. |
| `/zcode:code <задача>` | Отправляет самодостаточный промпт в ZCode на реализацию задачи прямо в рабочей директории. ZCode — отдельный процесс: он не видит контекст Claude Code, но сам читает `AGENTS.md`/`CLAUDE.md` из cwd. |
| `/zcode:review [ветка\|коммит\|путь]` | Собирает дифф через `git` (по умолчанию — рабочее дерево против `HEAD`) и отправляет его в ZCode на ревью. Без указанной цели ищет изменения в текущем дереве; если это не git-репозиторий или дифф пуст — команда завершится ошибкой, а не пустым прогоном. |
| `/zcode:status` | Показывает, что известно локально: путь к CLI, настроен ли провайдер, текущая модель. |

Общие флаги: `--model <id>` (модель на сессию, например `glm-5.3-flash` или
`zai/glm-5.3-flash`; по умолчанию `code` использует более дешёвую
`glm-5.3-flash`, `review` — более сильную `glm-5.3`), `--cwd <path>` (по
умолчанию текущая директория), `--json` (машиночитаемый вывод у `setup` и
`status`). Прогресс хода печатается в stderr, финальный ответ ZCode — в
stdout, так что вывод можно пайпить.

У `code` и `review` есть ещё `--timeout <секунды>` — таймаут хода в секундах
(внутри пересчитывается в миллисекунды для `runTurn`). Значения по умолчанию
намеренно выше библиотечного дефолта `session.mjs` (180с), потому что и
`code`, и `review` — это многораундовые операции с вызовом инструментов, а не
одиночный запрос: живой прогон `/zcode:review` на одном небольшом файле этого
репозитория занял шесть отдельных обращений к модели внутри одного хода. По
умолчанию `code` ждёт 900с, `review` — 600с; свой `--timeout` всегда важнее
дефолта. Если ход всё равно упирается в таймаут, сообщение об ошибке прямо
называет, сколько секунд было ожидание, и предлагает увеличить `--timeout`.

## Troubleshooting

Разобраны по симптомам — в том виде, в каком их реально печатает плагин.

### `Could not locate the ZCode CLI`

Не найден ни по `ZCODE_CLI`, ни внутри ZCode.app, ни на `PATH`. Варианты:

- поставить ZCode.app — CLI подхватится из бандла автоматически;
- установить CLI `zcode` и убедиться, что он на `PATH`;
- задать `ZCODE_CLI` абсолютным путём до `zcode`/`zcode.cjs`. Это должен быть
  именно файл: путь до самого бандла (`/Applications/ZCode.app`) не подойдёт.

### `Provider configured: no` / «no model provider configured»

ZCode найден, но провайдер моделей в нём не настроен. Плагин сам ключи не
прописывает — один раз выполните `zcode login` (с уже экспортированным
`ZAI_API_KEY`), затем повторно прогоните `/zcode:setup`.

### `session/setModel` отвергает модель / unknown model

Дефолтные модели (`glm-5.3-flash` для `code`, `glm-5.3` для `review`) могут
отсутствовать после свежего `zcode login` — тот регистрирует только
`glm-5.1`/`glm-4.7`. `/zcode:status` печатает список моделей из каталога;
передайте доступную явно: `--model <id>` (можно и с провайдером:
`--model zai/<id>`).

### `ZCode turn timed out after …ms`

Ход не уложился в таймаут. Сообщение называет, сколько секунд фактически
ждали, и предлагает удвоить лимит — например `--timeout 1800`. Дефолты (`code`
— 900с, `review` — 600с) уже выше библиотечных 180с; если упираетесь в них
регулярно, поднимайте `--timeout` явно.

### `review`: «is not inside a git repository»

`/zcode:review` собирает дифф через `git` и работает только внутри
репозитория. Запустите Claude Code из репозитория или передайте его через
`--cwd <path>`.

### `review`: «No changes to review»

Рабочее дерево не отличается от `HEAD`, и новых untracked-файлов нет. Если
ожидали изменений — проверьте, что они есть в той директории, которую
смотрите (см. `--cwd`). Нюанс: новые файлы не попадают в `git diff` — команда
лишь перечисляет их ZCode как untracked; чтобы новый код реально ушёл на
ревью в виде диффа, сначала `git add <файл>`.

### `ZCode turn failed` (код выхода 2)

ZCode отработал, но сам ход завершился ошибкой — в stderr будут `code` и
`retryable`. При `retryable: true` просто повторите команду. Если ошибка
стабильно повторяется, проверьте, что `ZAI_API_KEY` задан до запуска Claude
Code и что ключ действителен.

### Коды выхода

| Код | Значение |
|---|---|
| `0` | Успех |
| `1` | Ошибка самой команды: не найден CLI, провайдер не настроен, нет задачи у `code`, не git-репозиторий или нет диффа у `review` |
| `2` | Ход ZCode завершился `turn.failed` |
